#+TITLE: Portable NeLisp Japanese IME

This package is developed in the standalone =nelisp-ime= repository.  The
repository includes the NeLisp runtime needed to build and test the IME
adapters on macOS, Linux, and Windows.

* Overview

=nelisp-ime= is a Japanese conversion engine implemented in Elisp and runnable
by standalone NeLisp.  The same engine is intended to sit behind macOS
InputMethodKit, Linux Fcitx 5/IBus, and Windows TSF adapters.  Native code owns
only OS integration, event translation, and candidate-window presentation.

The current engine provides:

- independent composition sessions and live conversion after every key;
- JIS kana and incremental romaji normalization;
- dictionary lattice construction and minimum-cost path selection;
- segment and candidate selection;
- frequency learning with validated import/export;
- a versioned line-oriented JSON-RPC boundary;
- an indexed UTF-8 dictionary using the official SKK medium vocabulary,
  large-dictionary candidate ranking, grammatical kana priority, and
  conservative okurigana conjugation expansion.

* Public API

Framework core (=nelisp-ime.el=):

- =nelisp-ime-session-open= / =nelisp-ime-session-close=
- =nelisp-ime-feed=
- =nelisp-ime-engine-register= / =nelisp-ime-engine-get= / =nelisp-ime-engine-names=
- =nelisp-ime-default-engine= (variable, default =lattice=)
- =nelisp-ime-learning-import= / =nelisp-ime-learning-export=
- =nelisp-ime-protocol-handle-json=

Bundled lattice engine (=packages/nelisp-ime-lattice=, git submodule):

- =nelisp-ime-lattice-convert=
- =nelisp-ime-dictionary-install= / =nelisp-ime-dictionary-load-skk=

#+begin_src emacs-lisp
(nelisp-ime-session-open "macos:42" '(:input-style kana))
(nelisp-ime-feed "macos:42" '(:op :insert :text "かんじ"))
;; => ... :preedit "漢字" ...
(nelisp-ime-feed "macos:42" '(:op :commit))
#+end_src

Events support =:key=, =:insert=, =:backspace=, =:select-segment=,
=:select-candidate=, =:commit=, and =:cancel=.  Snapshots contain only portable
Lisp/JSON values.

A snapshot carries =:consumed=, =:reading=, =:preedit=, =:mode=, =:cursor=,
=:composition-start=, =:segments=, =:candidates=, =:candidate-index=,
=:active-segment=, =:pending=, and =:commit=.  =:composition-start= is =-1=
when no composition is open, which lets an adapter distinguish a direct
commit from an empty one.

* Robustness and housekeeping

An input method that signals mid-keystroke leaves the user unable to type,
so =nelisp-ime-feed= degrades instead: on an engine or event error it
returns the session's snapshot with =:consumed nil= and an =:error= string,
telling the adapter to pass the key through to the application.  Bind
=nelisp-ime-fail-open= to nil in engine development to surface the error.

- =nelisp-ime-session-status= returns a snapshot with no side effects, so
  mode indicators can poll without perturbing composition.
- =nelisp-ime-session-reset= discards composition state but keeps the
  session (its input style, context, and engine) — adapters call it to
  resynchronize after the application terminated a composition.
- =nelisp-ime-maintain= runs engine housekeeping (=gc=, =compact=) off the
  input path; engines without a =:maintain= hook return nil.
- Learning commits append one line to a journal
  (=nelisp-ime-learning-journal-append=) instead of rewriting the whole
  table; =nelisp-ime-learning-load= replays it and
  =nelisp-ime-learning-compact= folds and truncates it during idle time.

The protocol exposes the same surface: =ime/session.status=,
=ime/session.reset=, =ime/maintenance=, and =ime/learning.compact=.

* Architecture

#+begin_example
InputMethodKit / Fcitx 5 or IBus / TSF
                 |
          JSON-RPC protocol v1
                 |
      persistent standalone NeLisp
                 |
 key normalization -> lattice conversion -> learning
#+end_example

The generated dictionary file is used by standalone NeLisp because raw SKK
files require encoding and editor-buffer facilities.  See the
[[https://github.com/zawatton/nelisp-ime-lattice][nelisp-ime-lattice]] repository
(vendored at =packages/nelisp-ime-lattice=) for regeneration and
larger-dictionary substitution.

* Conversion engines

=nelisp-ime= is an IME *framework*: sessions, reading accumulation, candidate
and segment selection, learning, the JSON-RPC boundary, and the platform
adapters are engine-agnostic.  Conversion itself is pluggable:

#+begin_src emacs-lisp
(nelisp-ime-engine-register 'my-engine
                            :convert #'my-engine-convert   ; reading context -> plist
                            :learn   #'my-engine-learn)    ; optional, segments ->
(nelisp-ime-session-open "tsf:1" '(:input-style romaji :engine my-engine))
#+end_src

- =:convert= receives READING and CONTEXT and returns a plist with
  =:preedit=, =:candidates=, and =:segments= — the same contract as
  =nelisp-ime-converter-function=.
- =:feed= (for modal engines such as SKK) receives SESSION-ID, SESSION, and
  every EVENT before the default composition pipeline and returns the
  snapshot itself; such an engine may omit =:convert=.
- =:learn= (optional) replaces the framework frequency learning on commit.
- =:mode= (optional) receives SESSION and returns the input mode reported
  in snapshots, one of =nelisp-ime-modes= (=hiragana katakana latin
  wide-latin abbrev preedit candidate=).  Modal engines supply this so mode
  indicators and language-bar buttons track the engine, not a guess.
- =:reset= (optional) receives SESSION-ID and SESSION and discards
  engine-side composition state without closing the session.
- =:maintain= (optional) receives an operation symbol (=gc=, =compact=) and
  performs engine housekeeping off the input path.
- Sessions that do not select an engine use =nelisp-ime-converter-function=
  when set, then =nelisp-ime-default-engine= (default =lattice=).
- Over the protocol, =ime/session.open= accepts an optional ="engine"= field
  and =ime/initialize= reports registered names in ="engines"=.

Bundled engines:

| Name         | Source                                             | Behavior                                     |
|--------------+----------------------------------------------------+----------------------------------------------|
| =lattice=    | [[https://github.com/zawatton/nelisp-ime-lattice][nelisp-ime-lattice]] (submodule) | Minimum-cost dictionary lattice + SKK loader |
| =dictionary= | =nelisp-ime.el=                                    | Exact-reading alist lookup (reference)       |

The lattice engine lives in its own repository and is vendored here as the
git submodule =packages/nelisp-ime-lattice= (clone with =--recursive= or run
=git submodule update --init=).  IMEs such as an SKK-style modal engine plug
in the same way as separate packages.
